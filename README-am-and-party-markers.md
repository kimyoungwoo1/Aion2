# 아이온2 관리 — 오전 가능 / 파티 비고·징표

기존 `/workspaces/Aion2` 프로젝트의 **최상위 폴더**에서 덮어쓰는 업데이트입니다. ZIP에 `aion2/` 같은 상위 폴더가 없습니다.

## 수정 내용

1. 성역 일정 입력: `미입력`, `오전 가능`, `오후 가능`, `가능` 순서로 표시합니다.
   - 기존 DB의 `불가능` 상태는 삭제하지 않고 보존합니다. 해당 값이 저장되어 있는 사람에게만 `불가능 (기존 값)` 선택지가 임시로 나타납니다. 새 입력에서는 4개 항목을 사용합니다.
2. 날짜별 참여 인원 집계:
   - 오전 인원 = `가능` + `오전 가능`
   - 오후 인원 = `가능` + `오후 가능`
   - `미입력`은 참여 인원에 포함하지 않습니다.
3. `다같이 가능한 요일`: 모든 고정 참여자가 오전과 오후 모두 가능하면 `(가능)`, 오전만 가능하면 `(오전)`, 오후만 가능하면 `(오후)`로 표기합니다. 오전만 가능한 사람과 오후만 가능한 사람이 섞여 있으면 공통 가능 시간은 없으므로 표시하지 않습니다.
4. 성역별 1~4포스 / 포스당 1~2파티 / 파티당 5자리 구성 유지.
   - 각 **파티별 비고**(최대 150자)와 **파티 대표 징표** 선택 후 `비고 · 징표 저장` 버튼 클릭.
   - 이미 배정된 **참여자별 징표**도 선택 즉시 저장.
   - 징표: `1`, `2`, `3`, `4`, `5`, `★ 별`, `☠ 해골`, `☾ 달` 또는 `징표 없음`.
5. 기존 수요일 오전 5시(KST) 일정·주간 숙제 초기화, 4↔3성역 일정 연동, 숙제 닉네임별 화면, 기존 접속 코드와 캐릭터·파티 배정은 유지합니다.

## 적용 명령어

```bash
# 선택 사항: 운영 DB 백업
npx wrangler d1 export aion2-db --remote --output=../aion2-db-before-markers.sql

# 이 ZIP을 Codespaces의 /workspaces/Aion2에 올린 다음
unzip -o Aion2_AM_Availability_Party_Notes_Markers.zip

# 필수: 파티 비고/징표 저장용 테이블과 컬럼 추가
npx wrangler d1 migrations apply aion2-db --remote

# 실제 배포
npx wrangler deploy

# 배포 후 로그인 API 확인
curl -i https://aion2.ksmsy1.workers.dev/api/me
```

`migrations/0009_party_notes_and_markers.sql`은 기존 `0001`~`0008` 마이그레이션이 적용된 DB에서 사용합니다. 삭제·초기화 쿼리는 포함하지 않았습니다.

`wrangler.jsonc`, Secret(`ACCESS_CODE`), D1 UUID, API Service Binding은 이번 ZIP에 없으므로 덮어쓰지 않습니다.

## 확인 시나리오

- 슬롱으로 로그인해 4성역 날짜별 `오전 가능` 저장 -> 3성역의 동일 고정 참가자가 같은 상태 표시되는지 확인.
- 전원이 `가능`이면 `수요일 10/28 (가능)`, 전원이 `가능` 또는 `오전 가능`이면 `(오전)`, `가능` 또는 `오후 가능`이면 `(오후)`로 표시되는지 확인.
- 4성역 > 참여자·파티 편성 > 1포스 1파티에서 `파티 비고`, `파티 징표` 선택 후 저장 -> 새로고침해도 유지되는지 확인.
- 파티에 배정된 캐릭터 옆에서 징표를 선택 -> 새로고침해도 유지되고 다른 성역의 같은 캐릭터에는 영향이 없는지 확인.

이번 변경은 **직접 배포하기 전까지 운영 사이트에 반영되지 않습니다.**
