# 아이온2 관리 — 성역 고정 참여자 및 4↔3 완전 자동 동기화

이번 업데이트는 캐릭터 관리, 전투력 갱신, 공용 접속 코드, Worker/D1/Service Binding 설정을 변경하지 않습니다.

## 적용

기존 `/workspaces/Aion2` 최상위에 ZIP을 업로드한 다음:

```bash
unzip -o Aion2_Sanctuary_FixedMembers_AutoSync.zip
npx wrangler d1 migrations apply aion2-db --remote
npx wrangler deploy
```

최초 한 번만 SQL `migrations/0004_sanctuary_members_and_shared.sql`이 적용됩니다. **마이그레이션 적용을 생략하면 성역 API가 오류 납니다.** 기존 `wrangler.jsonc`, `ACCESS_CODE`, D1 ID는 건드리지 않습니다.

GitHub 자동 배포에 이전 코드가 덮어씌워지지 않도록 확인 후:

```bash
git add src/index.js public/index.html public/app.js migrations/0004_sanctuary_members_and_shared.sql README-fixed-participants.md
git commit -m "Persist sanctuary rosters and share 4-3 availability"
git push origin main
```

## 동작 방식

- **고정 명단 관리:** 4성역, 3성역, 2성역 각각 `고정 참여자 명단`에서 닉네임을 줄바꿈 또는 쉼표로 입력하여 한 번만 등록합니다. 해당 성역의 명단은 **모든 주차**의 전체 참여 일정에 자동으로 표시됩니다. 매주 월요일마다 재등록하지 않습니다.
- **기존 데이터:** 이전 주차에서 한 번이라도 일정을 저장했던 닉네임은 해당 성역의 고정 명단으로 최초 마이그레이션 때 자동 이전됩니다. 기존 캐릭터 DB는 변경되지 않습니다.
- **4성역 ↔ 3성역:** 명단이 **각 성역에 모두 존재하는 같은 닉네임**이라면 주차별 7일 가능 여부를 단일 공통 데이터로 저장합니다. 어느 성역에서든 저장하면 다른 성역으로 이동했을 때 **별도의 내 일정 저장 없이** 자동 반영됩니다. 성역에 들어가 있다고 해서 다른 성역의 고정 명단에 자동 가입되지는 않습니다.
- **2성역 침식:** 일정과 명단 모두 독립적입니다.
- **비고:** 4성역과 3성역의 비고는 각각 별도로 저장됩니다.
- **미입력:** 아직 일정을 기록하지 않은 참여자도 전체 일정 표에서 `미입력`으로 표시되며, 참여 가능 인원과 전원 가능 요일 계산에서는 가능자로 집계되지 않습니다.
- **날짜별 인원:** 고정 명단 전체를 분모로 계산합니다. `가능`은 오전·오후 모두 가능, `오후 가능`은 오후만 가능으로 집계합니다. 카드 하단의 `다같이 가능한 요일`은 고정 명단의 모든 인원이 가능한 날짜만 표시합니다.
- **명단에서 제외:** 해당 성역 명단에서만 숨깁니다. 다른 성역의 명단과 공통 일정은 보존합니다. 과거의 일정 기록도 데이터베이스에서 즉시 삭제하지 않습니다.
- **이번 주 일정 초기화:** 4/3의 공통 가능 여부만 초기화하며 명단은 유지합니다. 성역별 비고는 선택한 성역만 지워집니다.

## 기존 4·3성역 일정이 서로 다른 경우

마이그레이션 시 **더 최근에 수정된 값**을 첫 공통 일정으로 사용합니다. 수정 시각이 같다면 4성역 값을 선택합니다. 이전 `sanctuary_schedules` 행들은 삭제하지 않습니다.

## 테스트 예시

1. 4성역 고정 명단에 `슬롱` 등록.
2. 3성역 고정 명단에도 `슬롱` 등록. 이때 일정 저장 불필요.
3. 4성역에서 월 `가능`, 화 `오후 가능`을 선택해 **한 번만 저장**.
4. 3성역으로 이동하면 자동으로 동일한 값과 참여 인원 집계가 표시됨.
5. 다음 주로 이동해도 두 명단에 `슬롱`이 보이고, 해당 주차의 가능 여부는 `미입력`으로 새로 시작됨.

**주의:** 공용 접속 코드 로그인은 닉네임의 신원을 검증하지 않습니다. 이 방식을 유지하면 접속 코드를 아는 사람은 고정 명단을 수정하고 같은 닉네임으로 일정을 입력할 수 있습니다.
