# 아이온2 관리 – 4성역/3성역 동일 참여자 일정 동기화

## 변경 내용
- **4성역(델트라스)** ↔ **3성역(무스펠)**: 같은 닉네임이 같은 주차의 양쪽 성역에 참여하면 `가능 / 오후 가능 / 불가능 / 미입력` 요일별 상태를 양방향 동기화합니다.
- **2성역(침식)**은 기존처럼 완전히 독립적입니다.
- 한쪽에만 참여하던 사용자가 다른 성역 탭을 열면 **'다른 성역 일정 가져와 참여'** 버튼이 표시됩니다. 버튼 한 번으로 일정 복사 및 참여 등록을 마칩니다.
- 참여하지 않는 다른 성역에 사람을 자동 등록하지 않습니다. 양쪽에 이미 등록되어 있다면 어느 쪽에서든 저장 시 동기화됩니다.
- **비고는 성역별로 독립**합니다. (이전 구글시트의 B:H 요일 값만 동기화하는 방식과 유사)
- 성역 일정 삭제 시 해당 성역의 등록만 지우고 다른 성역의 일정은 유지하며 연동도 해제됩니다.
- 기존 두 성역에 서로 다른 일정이 이미 저장되어 있다면 그 상태를 보존합니다. 사용자가 어느 한쪽에서 다음에 저장할 때 그 일정으로 일치시킵니다.
- 주차별로 독립이며, 다른 주차 일정에는 영향을 주지 않습니다.

## 변경 파일
- `public/index.html`
- `public/app.js`
- `src/index.js`

**DB 스키마 변경 없음. 추가 SQL 마이그레이션 불필요.** 기존 캐릭터 및 성역 데이터를 그대로 사용합니다.
기존 `wrangler.jsonc`, D1 ID, `ACCESS_CODE`는 변경하지 않습니다.

## 적용 순서 (Codespaces 프로젝트 최상위에서)
```bash
unzip -o aion2-sanctuary-sync.zip
node --check src/index.js
node --check public/app.js
npx wrangler deploy
```

GitHub 자동 배포를 연동했다면 코드 커밋도 진행하세요.
```bash
git add src/index.js public/index.html public/app.js
git commit -m "Sync 4th and 3rd sanctuary schedules per participant"
git push origin main
```

### 확인 방법
1. `슬롱`으로 로그인하여 4성역에서 이번 주 일정을 저장합니다.
2. 3성역에 이동하면 `4성역 일정 가져와 참여` 버튼이 나옵니다. 누르면 요일 값이 복사됩니다.
3. 3성역에서 요일 하나를 수정하고 저장한 뒤 4성역으로 이동하면 수정된 요일이 반영됩니다.
4. 2성역은 그대로 별도 관리됩니다.

> 공용 접속 코드 방식은 닉네임의 실제 소유권을 검증하지 않습니다. 다른 사용자가 동일한 닉네임으로 로그인하면 해당 일정 변경이 가능합니다.
